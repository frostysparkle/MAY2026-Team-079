Register

Endpoint: `POST /auth/register`

Authentication: Not required

Request Body:

{
  "email": "participant@example.com",
  "password": "at-least-eight-characters"
}

#"id": "participant-id", created from email id, ex- 23f3001726@ds.study.iitm.ac.in is DS23F3001726, unique and primary key for each user
#creates a set of public and private key for each user (asymmetric encryption)

Response:

200 ok /or other appropriate response

Request Password Reset

Endpoint: `POST /auth/password/forgot`

Authentication: Not required

Request Body:

{
  "email": "participant@example.com"
}

Response:

{
  "message": "If the account exists, a reset link has been sent.",
  "dev_reset_url": null
}

`dev_reset_url` is expected only in an enabled development environment.

---

Reset Password

Endpoint: `POST /auth/password/reset`

Authentication: Not required

Request Body:

{
  "token": "single-use-reset-token",
  "new_password": "new-account-password"
}

Response:

{
  "message": "Password reset successfully."
}

---

Change Password

Endpoint: `POST /auth/password/change`

Authentication: Bearer JWT Token

Request Body:

{
  "current_password": "current-password",
  "new_password": "new-password"
}

Response:

{
  "message": "Password changed successfully.",
  "access_token": "<REPLACEMENT_JWT_TOKEN>"
}

Note: The frontend replaces its stored token with `access_token`.
